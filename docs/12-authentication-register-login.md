# Authentication - User Registration & Login

# 1. Introduction

Authentication is the process of verifying the identity of a user.

Instead of allowing anyone to access the application, users must first register and then log in using their credentials.

---

# 2. User Model

A separate User model is created to store user information.

Example:

```javascript
const userSchema = new mongoose.Schema({
    name:{
        type:String,
        required:true,
        trim:true
    },
    email:{
        type:String,
        required:true,
        trim:true,
        unique:true
    },
    password:{
        type:String,
        required:true,
        minlength:7
    }
});
```

---

# 3. Why Passwords Should Never Be Stored Directly

Never store passwords in plain text.

Wrong:

```
Password:
12345678
```

If the database is leaked, every user's password becomes visible.

Instead, passwords should be converted into hashed values before storing them.

---

# 4. bcrypt

bcrypt is a library used to hash passwords.

Install:

```bash
npm install bcrypt
```

Import:

```javascript
const bcrypt = require("bcrypt");
```

Hash Password:

```javascript
const hashedPassword = await bcrypt.hash(req.body.password, 10);
```

The number **10** represents the salt rounds.

Higher values increase security but also increase processing time.

---

# 5. Register User

Registration Flow:

```
Client
   │
   ▼
Register Request
   │
   ▼
Hash Password
   │
   ▼
Store User in MongoDB
   │
   ▼
Success Response without revealing the password
```

Example:

```javascript
const hashedPassword = await bcrypt.hash(req.body.password,10);

req.body.password = hashedPassword;

const user = await User.create(req.body);

user.password = undefined;
```

---

# 6. Login Flow :- Important

During login:

1. Find the user by email.
2. If email does not exist, return 401.
3. Compare entered password with stored hashed password.
4. If password is incorrect, return 401.
5. Generate JWT.
6. Return the token.

Flow:

```
Client
   │
   ▼
Email + Password
   │
   ▼
Find User
   │
   ▼
bcrypt.compare()
   │
   ▼
Generate JWT
   │
   ▼
Send Token
```

---

# 7. Comparing Passwords

bcrypt compares the entered password with the stored hashed password.

Example:

```javascript
const isPasswordValid = await bcrypt.compare(
    req.body.password,
    user.password
);
```

If:

```javascript
isPasswordValid === false
```

return:

```javascript
res.status(401).json({
    message:"Invalid Email or Password",
    success:false
});
```

---

# 8. JSON Web Token (JWT)

JWT stands for **JSON Web Token**.

A JWT acts like a digital identity card generated by the server after successful login.

Instead of sending the password with every request, the client sends the JWT.

---

# 9. Installing JWT

```bash
npm install jsonwebtoken
```

Import:

```javascript
const jwt = require("jsonwebtoken");
```

---

# 10. Secret Key

Store the secret key inside `.env`.

Example:

```env
JWT_SECRET=mySuperSecretKey
```

Access:

```javascript
process.env.JWT_SECRET
```

Never hardcode secret keys inside JavaScript files.

---

# 11. Generating JWT

Syntax:

```javascript
jwt.sign(
    payload,
    secretKey,
    options
);
```

Project Udaan:

```javascript
const token = jwt.sign(
    { id:user._id },
    process.env.JWT_SECRET,
    {
        expiresIn:"7d"
    }
);
```

---

# 12. Login Response

After successful login:

```javascript
res.status(200).json({
    message:"User Logged In",
    success:true,
    token:token
});
```

The client stores this token and sends it with future requests.

---

# 13. Why Use JWT?

Without JWT:

```
Every request
↓

Email
Password
```

With JWT:

```
Login Once
↓

Receive Token
↓

Future Requests
↓

Token Only
```

This is more secure than repeatedly sending passwords.

---

# 14. Key Points

* Authentication verifies user identity.
* Passwords should always be hashed.
* bcrypt hashes and compares passwords.
* JWT is generated after successful login.
* JWT contains user identification information called the payload.
* Secret keys should always be stored inside `.env`.
* Clients send JWT instead of passwords after login.

---



# Summary

Authentication ensures that only valid users can access the application. Passwords are hashed using bcrypt before being stored in MongoDB. During login, bcrypt verifies the password using `bcrypt.compare()` method, and after successful verification, a JWT is generated. The client stores this token and sends it with future requests instead of repeatedly sending the user's password.
